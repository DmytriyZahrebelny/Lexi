# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Lexi is a vocabulary-learning app: users add English words, the backend enriches each one via a dictionary lookup (definition, part of speech, example sentence, audio), and words are reviewed in flashcard sessions scheduled by the SM-2 spaced-repetition algorithm. See `PRD.md` for full product scope and decisions. The SM-2 review engine and word management are not implemented yet — only auth is built so far.

pnpm workspace monorepo:
- `apps/api` — Hono + Drizzle ORM + `pg`, PostgreSQL, TypeScript.
- `apps/web` — Next.js (App Router) + TanStack Query + MUI + react-hook-form + Effect, TypeScript.
- `packages/shared` — zod schemas/types shared between `api` and `web`, consumed as raw TypeScript source (not built — see Gotchas).

## Commands

Install once at the root (`pnpm install`); it covers all workspace packages.

```bash
pnpm dev:api              # run apps/api (tsx watch)
pnpm dev:web              # run apps/web (next dev)
pnpm build                # pnpm -r build (currently only apps/web has a real build step)
pnpm test                 # vitest run in every package that has a test script
pnpm lint                 # eslint . (root-level flat config, whole monorepo in one pass)
pnpm typecheck            # tsc --noEmit in every package
pnpm db:generate          # drizzle-kit generate (apps/api)
pnpm db:migrate           # apply pending migrations (apps/api)
```

Per-package equivalents: `pnpm --filter api <script>`, `pnpm --filter web <script>`, `pnpm --filter @lexi/shared <script>`.

Run a single test file: `pnpm --filter api exec vitest run src/lib/__tests__/password.test.ts` (or `--filter web`, `--filter @lexi/shared`). Vitest's default watch mode also works: `pnpm --filter web exec vitest src/components/__tests__/RegisterForm.test.tsx`.

Local Postgres: `docker compose up -d postgres` (or Postgres.app / any local Postgres — `apps/api/.env`'s `DATABASE_URL` just needs to point at it). Copy `apps/api/.env.example` → `.env` and `apps/web/.env.example` → `.env` before running either app; `apps/api`'s `JWT_SECRET` must be at least 32 characters.

## Architecture

**Shared contracts.** `packages/shared` holds zod schemas (`registerSchema`, `loginSchema`, `userSchema`, etc.) that are the single source of truth for API request/response shapes. Both `apps/api` (via `@hono/zod-validator`) and `apps/web` (via `@hookform/resolvers/zod` in forms, and to decode API responses) import the same schemas from `@lexi/shared`. It has no build step — `main`/`types` point straight at `src/index.ts` — so `apps/web/next.config.ts` must list it in `transpilePackages` or Turbopack fails to resolve it (see Gotchas).

**Backend auth flow** (`apps/api/src`): `routes/auth.ts` defines `POST /auth/register|login|logout`, `GET /auth/me`. Passwords are hashed with `bcryptjs` (`lib/password.ts`). Sessions are JWTs signed via `hono/jwt` (`lib/session.ts`) stored in an httpOnly `lexi_session` cookie; `middleware/auth.ts`'s `requireAuth` reads that cookie and is the actual authorization boundary. `db/schema.ts` is the Drizzle table definitions; `db/client.ts` wires up the `pg` Pool + Drizzle instance; migrations live in `apps/api/drizzle/` (generated by `drizzle-kit`, applied by `db/migrate.ts` — commit both the `.sql` files and `drizzle/meta/`). CORS (`hono/cors` in `src/index.ts`) is scoped to `WEB_ORIGIN` with `credentials: true` — required because the web app calls the API cross-origin with cookies; don't remove it.

**Frontend auth flow** (`apps/web/src`): `proxy.ts` (Next 16's renamed `middleware.ts` — see Gotchas) redirects based only on *presence* of the `lexi_session` cookie, for UX; it does not validate the JWT — `requireAuth` on the API is the real enforcement. Data fetching goes through a small Effect-based client: `lib/api/http.ts` wraps `fetch` in `Effect`s with tagged errors (`NetworkError`, `HttpError`), `lib/api/auth.ts` builds the auth-specific calls on top of it and decodes responses against the `@lexi/shared` zod schemas, and `lib/query/run-effect.ts`'s `runEffectPromise` bridges an `Effect` into a plain `Promise` (via `Effect.either`, so the rejection is the tagged error itself, not an Effect `FiberFailure`) for use as a TanStack Query `queryFn`/`mutationFn` — see `lib/query/auth.ts` for the pattern (`useMe`, `useRegister`, `useLogin`, `useLogout`). `providers/AppProviders.tsx` wires up MUI's theme/`AppRouterCacheProvider` and the `QueryClientProvider`.

## Conventions specific to this repo

- **No default exports/imports** in application code — use named exports/imports everywhere. Enforced by `eslint.config.mjs`'s `no-restricted-syntax` rule. The only exemptions (configured in that same file) are places with no alternative by contract: Next.js's `page.tsx`/`layout.tsx`/etc. (framework requires a default-exported component) and tool config files (`vitest.config.ts`, `drizzle.config.ts`, `next.config.ts`, `eslint.config.mjs` itself) whose underlying packages only ship a default export.
- **Filenames are kebab-case or PascalCase, never camelCase** — enforced by `eslint-plugin-unicorn`'s `filename-case` rule in `eslint.config.mjs`. React component files use PascalCase (`RegisterForm.tsx`); everything else is kebab-case (`run-effect.ts`).
- **Tests live in a `__tests__` subfolder next to the file they test** (e.g. `src/lib/__tests__/password.test.ts`), not as a sibling `*.test.ts`. The `__tests__` directory name is explicitly exempted from the filename-case rule.

## Gotchas

- **TypeScript 7 vs. `typescript-eslint`**: `apps/api`, `apps/web`, and `packages/shared` each depend on real `typescript@^7`. But `typescript-eslint` (used by the root `eslint.config.mjs`) hard-errors on TypeScript 7. The root `package.json`'s own `typescript` devDependency is therefore aliased to `npm:@typescript/typescript6` (the official compat shim) — this only affects what the root-level lint config resolves; because pnpm doesn't hoist across workspace packages, each app/package still typechecks with real TypeScript 7 independently. Don't "fix" the root alias back to `^7` — it will break `pnpm lint` again.
- **`apps/web` runs Next.js 16**, which has breaking changes versus older Next versions (training-data-era APIs may not apply). Notably `middleware.ts` is renamed to `proxy.ts` (exported function renamed `middleware` → `proxy`). Check `apps/web/node_modules/next/dist/docs/` before assuming an App Router API/convention is current. `apps/web/AGENTS.md`/`CLAUDE.md` are generated by `next dev` itself (referencing this) and are meant to be committed, not deleted.
- **`packages/shared` is unbuilt raw TypeScript.** Turbopack won't transpile a workspace package by default; `apps/web/next.config.ts` sets `transpilePackages: ["@lexi/shared"]` to handle this. If a new shared package is added later, it needs the same treatment.
